# Zawed Supply — منصة توريدات المكاتب (B2B)

منصة توريد مستلزمات مكتبية للشركات والمنظمات في السودان (نحن **المورّد**، لسنا سوقاً
وسيطاً). العملاء يطلبون من كتالوجنا ونحن نُنفّذ، والدخل من هامش الربح + عقود توريد شهرية.

> B2B e-procurement platform for office supplies in Khartoum, Sudan. Arabic-first
> (RTL) with an English toggle. Built to survive ~78% inflation, a depreciating
> SDG, and intermittent low-bandwidth connectivity.

## المبادئ المعمارية (تفرضها ظروف السوق)

- **لا يُخزَّن أي سعر نهائي بالجنيه أبداً.** يُحسب لحظياً:
  `التكلفة بالدولار × (1 + هامش الربح) × سعر الصرف`، ثم يُطبَّق أفضل خصم.
- **لقطة السعر:** عند إنشاء الطلب تُجمَّد قيمة الوحدة وسعر الصرف على البنود — فالمستندات
  التاريخية لا تتغيّر عند تحرّك سعر الصرف.
- **الأسعار تُحسب على الخادم فقط.** العميل لا يستطيع إرسال سعر — `place_order()` تعيد
  تسعير كل بند داخل قاعدة البيانات، وسياسات RLS تمنع الكتابة المباشرة على `order_items`.
- **يتحمّل ضعف الشبكة:** تسعير الكتالوج كله في **استدعاء واحد**، وتخزين مؤقت يبقى بعد
  إعادة التحميل، وشريط تنبيه عند انقطاع الاتصال.
- **موجّه للأجهزة الضعيفة:** حزمة JS أولية **~113 KB مضغوطة**، وشاشات الإدارة مفصولة
  (code-split) فلا يُنزّلها العملاء.
- **الدفع خارج المنصة:** تحويل بنكي / بنكك / فوري / نقداً — المنصة تُسجّل حالة الدفع فقط.

| الطبقة | التقنية |

## الأدوار (مفروضة عبر RLS وليس إخفاء الواجهة فقط)

`admin` · `sales` · `warehouse` · `customer_admin` · `customer_requester`

للموظفين فقط) — ومع ذلك يستطيع تسعير المنتجات عبر دوال `SECURITY DEFINER`.

## التشغيل

### 1) قاعدة البيانات (Supabase)

```bash
supabase link --project-ref YOUR_PROJECT_REF
supabase db push                              # يطبّق supabase/migrations بالترتيب
psql "$SUPABASE_DB_URL" -f supabase/seed.sql            # الكتالوج
psql "$SUPABASE_DB_URL" -f supabase/seed_demo_users.sql # مستخدمون تجريبيون
```

أو من **SQL Editor** في لوحة Supabase: الصق ملفات `migrations/*` بالترتيب ثم ملفي البذور.

### 2) الواجهة

```bash
cp .env.example .env      # ضع VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY
npm install
npm run dev               # http://localhost:5173
```

> إذا لم تُضبط المتغيّرات، يعرض التطبيق شاشة إعداد واضحة بدل الانهيار.

## ما تم إنجازه — المرحلة 1 (MVP) مكتملة

### طبقة قاعدة البيانات — `supabase/`

```
migrations/
  20260812090000_schema.sql     16 جدولاً + ترقيم المستندات + سجل التدقيق + فهرس بحث عربي
  20260812090100_pricing.sql    get_price() — محرك التسعير الحي
  20260812090200_rls.sql        تفعيل RLS + سياسات كل الجداول + دوال الأدوار
  20260812090300_order_rpc.sql  get_catalog_prices() + place_order() وإغلاق ثغرة الكتابة
seed.sql                        8 أصناف + 44 منتجاً مكتبياً + أسعار + مخزون + خصومات كمية
seed_demo_users.sql             مدير + شركة NGO + طلب/فاتورة/دفعة تجريبية
```

**محرك التسعير `get_price(product_id, company_id, qty)`** يُرجع
`{ unit_price_sdg, unit_price_usd, fx_rate_used, discount_applied, tier_name }`:
السعر الأساسي بالدولار ← أفضل خصم (العقدي للشركة يتقدّم على العام، والأعمق كمية) ←
تحويل بسعر الصرف الأحدث ← تقريب الجنيه لأعلى لأقرب 100.

### الواجهة — `src/`

```
src/
  i18n/          نظام لغتين (عربي افتراضي + إنجليزي) مع قلب اتجاه الصفحة
  context/       AuthProvider (جلسة + ملف + شركة) · CartProvider (سلة لكل مستخدم)
  hooks/         استعلامات TanStack Query + حالة الاتصال
  components/    مكوّنات الواجهة + الهيكل (شريط جانبي/سفلي) + شارات الحالة
  pages/         الدخول · الكتالوج · المنتج · السلة · التأكيد · الطلبات
  pages/admin/   لوحة التحكم · سعر الصرف · كل الطلبات
```

**شاشات العميل:** تسجيل الدخول · الكتالوج (بحث عربي يتجاهل التشكيل + تصفية بالأصناف) ·
صفحة المنتج (سعر حي حسب الكمية + جدول خصومات + تنبيه «اطلب 10 ووفّر 5%») · السلة
(تحذير الحد الأدنى والمخزون) · التأكيد (عنوان، تاريخ، **رقم PO إجباري إن تطلّبته الشركة**) ·
طلباتي + التفاصيل + إعادة الطلب بضغطة.

**شاشات الإدارة:** لوحة تحكم (طلبات اليوم، بانتظار المراجعة، مخزون منخفض، **تحذير إذا
لم يُحدَّث سعر الصرف منذ 24 ساعة**) · تحديث سعر الصرف بحقل واحد كبير مع سجل التغييرات ·
كل الطلبات مع تصفية وتغيير الحالة.

## المرحلتان 2 و3 — الحالة الحالية (العمل جارٍ)

### ✅ مكتمل ومُختبَر على PostgreSQL — طبقة قاعدة البيانات

`20260812090400_phase2_documents.sql` — عروض الأسعار والفواتير والمدفوعات وسير الموافقات:

| الدالة | ماذا تفعل | تم التحقق |
|--------|-----------|-----------|
| `create_quotation()` | عرض سعر مُسعّر على الخادم بصلاحية 7 أيام | ✅ |
| `accept_quotation()` | يحوّله لطلب **بأسعار العرض المجمّدة** | ✅ ارتفع سعر الصرف 50% والسعر المعروض لم يتغيّر (10,500 مقابل 15,700 حياً) |
| `issue_invoice()` | فاتورة من الطلب مع تاريخ استحقاق حسب شروط الشركة | ✅ |
| `record_payment()` | يسجّل دفعة ويحدّث الرصيد والحالة | ✅ جزئي → مسدَّد، ويرفض تجاوز الرصيد |
| `decide_internal_approval()` | موافقة مسؤول الشركة على طلب موظفه | ✅ الرفض يلغي الطلب **ويحرّر المخزون المحجوز** ولا يستطيع الموظف الموافقة لنفسه |
| `expire_quotations()` / `refresh_overdue_invoices()` | انتهاء الصلاحية والمتأخرات | ✅ |

`20260812090500_phase3_recurring_reports.sql` — الطلبات المتكرّرة والتقارير:

| الدالة | تم التحقق |
|--------|-----------|
| `run_recurring_order()` | ✅ يولّد طلباً بأسعار اليوم ويقدّم موعد التشغيل التالي |
| `report_revenue_by_month()` · `report_top_customers()` · `report_top_products()` | ✅ |
| `report_margin()` | ✅ يستخدم **لقطة التكلفة** وقت البيع (هامش 76.7% في الاختبار) |
| `report_aged_receivables()` | ✅ شرائح 30/60/90 يوماً |
| عزل التقارير عن العملاء | ✅ العميل يرى 0 صفوف |

**إصلاحات لعيوب حقيقية اكتُشفت أثناء البناء:**
- `orders` لم يكن فيها عمود `notes` — ملاحظات العميل عند التأكيد كانت **تُهمَل بصمت** منذ
  المرحلة 1. تمت إضافة العمود.
- أُضيفت `cost_usd_snapshot` على بنود الطلب وعرض السعر، فصار تقرير الهامش دقيقاً بدل أن
  يُحتسب على تكلفة اليوم.

### ✅ مكتمل — محرك PDF العربي (`src/lib/pdf/`)

أصعب نقطة تقنية: مكتبات PDF **لا تشكّل العربية ولا تعيد ترتيبها**، فتظهر الحروف مقطّعة
ومعكوسة. الحل المطبَّق في `arabic.ts`: تشكيل الحروف (`arabic-reshaper`) ثم إعادة الترتيب
البصري بخوارزمية Unicode ثنائية الاتجاه (`bidi-js`) مع عكس الأقواس.

- `documents.ts` — أربعة مستندات ثنائية اللغة: **عرض سعر · فاتورة مبدئية · فاتورة ضريبية ·
  إذن تسليم** (بخانة توقيع المستلم)، بترتيب أعمدة معكوس ليُقرأ من اليمين.
- `numberToArabicWords.ts` — المبلغ كتابةً بالعربي (مطلوب على الفواتير).
- الخط والمكتبة يُحمّلان **عند الطلب فقط**، فلم تتغيّر حزمة الدخول (18.18 kB مضغوطة).

### ⏳ المتبقّي للجلسة القادمة

1. **التحقق البصري من مخرجات PDF** — توليد المستندات في متصفح حقيقي وعرضها كصورة
   للتأكد من اتصال الحروف العربية (لم يُنفَّذ بعد).
2. **شاشات المرحلة 2:** منشئ عروض الأسعار (اختيار شركة + بنود + إرسال عبر واتساب) ·
   قائمة الفواتير · تسجيل المدفوعات.
3. **شاشات المرحلة 3:** الطلبات المتكرّرة · صندوق الموافقات لمسؤول الشركة · التقارير.
4. **طبقة PWA:** service worker + طابور الطلبات دون اتصال («سيتم الإرسال عند عودة الاتصال»).
